# eshlink-cms on jenyapix

The site's content — the portfolio galleries and the Instagram strip — is served
by the shared [`minivoper/eshlink-cms`](https://github.com/minivoper/eshlink-cms)
package. The Blade views, the routes and `App\Support\Portfolio`'s method
signatures did not change; only where the data comes from did.

## Content types

`app/Cms/Types/` holds this site's thin content-type definitions. Everything
reusable lives in the package.

| Type | Key | Shape | Backing |
|---|---|---|---|
| `GalleryType` | `gallery` | collection, slugged, orderable: `title`, `slug`, `year`, `blurb`, `cover`, `images[]` (`image`, `alt`, `width`) | `EntrySource` |
| `InstagramFeedType` | `instagram_feed` | singleton: `handle`, `url`, `posts[]` (`file`, `href`, `alt`, `video`) | `EntrySource` |

`Portfolio::galleries()`/`gallery()`/`instagram()` read the published entries
(`Cms::published()` / `Cms::all()`), map them back to the exact arrays the views
expect (the gallery repeater's `image` becomes each photo's `file`; `count` is
derived from the number of photographs), and memoise per request. The CMS caches
the underlying reads behind a version token that every publish bumps.

## Local development: composer path repository

For local dev the package is a **path repository** symlinked from the sibling
checkout, so edits to the package are picked up without a reinstall:

```jsonc
// composer.json
"repositories": [
    { "type": "path", "url": "../eshlink-cms", "options": { "symlink": true } }
],
"require": {
    "minivoper/eshlink-cms": "@dev"
}
```

```bash
git clone git@github.com:minivoper/eshlink-cms.git ../eshlink-cms   # sibling of this repo
composer update minivoper/eshlink-cms
```

**Do not commit the path-repo `composer.lock`.** The lock that results from a
path repository pins the dependency to a local symlink, which is meaningless on
any other machine and on deploy. Production installs the package from a VCS tag
(the same way marina does) — wiring that tag into the deploy config is a separate
step. Keep `composer.json`'s `repositories`/`require` entries; leave the lock's
path pin out of any commit.

## Install and import

```bash
php artisan vendor:publish --tag=cms-config   # writes config/cms.php (already committed)
php artisan cms:install --seed-defaults        # migrates cms_* tables; seeds the Instagram default
php artisan portfolio:import                    # imports content/galleries.json + content/instagram.json
```

`portfolio:import` is idempotent by slug — rerun it as often as you like; it
updates and republishes rather than duplicating. It also reorders the galleries
to file order, because a fresh collection would otherwise sort newest-first and
reverse the order the home page indexes into.

`content/galleries.json` and `content/instagram.json` stay in the repo as the
import source and as a plain-text record of the seeded content.

## Site availability

The site ships in `live` mode. `maintenance` and `locked` are flipped at runtime
from the admin dashboard or the `set_site_mode` MCP tool (both gated on the
`site.availability` ability) and enforced by the `SiteAvailability` middleware
wired in `bootstrap/app.php`. The read fails open to `live`.

## Discovery surface

`/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`, `/humans.txt` and
`/feed.xml` are generated by the package from published content on the production
host and 404 everywhere else. Galleries are declared to live under `/work` (not
`/gallery`) via `config('cms.seo.url_prefixes')`.
